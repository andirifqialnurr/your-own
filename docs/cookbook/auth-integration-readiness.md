### Source-backed blockers, not newly executed failures

1. **Changed store semantics conflict with the published refresh contract.** The published `RefreshTokenRecord.claims` is optional. `@nestjs/authentication/testing` saves a bare record and arbitrary claims, then requires a later successor insert into an already revoked family while its tombstone stays effective. The account prototype's `Store.saveRefreshToken()` instead requires `claims.gid`, matching owned claim bindings and a nonrevoked grant/family. Those rules can be appropriate in an issuance coordinator, but the prototype cannot simply be declared a generic contract-compatible store. Earlier **24 published cases** passed a different adapter; the later synthetic type/import pass did not rerun these semantics. This is static comparison, not a runtime contract-test failure. Do not inject test-only claims, skip late-insert assertions or swap in a different permissive test adapter to manufacture a pass.
2. **Full trusted principal projection is absent.** The prototype provider returns `{id}`. Its `live()` query checks account/grant/family/revision/assurance facts, but does not select verified email or exact capabilities; seed users were already verified and staff was a fixture boolean. Library verified-email guarding defaults to `user.emailVerified === true`. The future principal must project this from current durable state, and S0 requires exact current capability facts—not a cast, client flag or bool-to-role shortcut. `ActorContext` must contain no password/hash/token/email address or raw DB row.
3. **Cookie write ownership is unresolved.** Prototype `cookie()` calls session validation without `Context.run()`, while the store touch requires an active typed unit of work. The library catches touch errors and returns the previously read live session. Successful idle sliding, mandatory-write failure behavior, deletion/rotation and absolute expiry therefore need real SQL/HTTP proof. Do not disable idle expiry, permit global writes or mistake a swallowed write for durable activity. The exact failure policy must be explicitly defined/tested; this packet does not choose production idle values or silently replace the library's documented best-effort semantics.
4. **Provider fallback and cookie side effects require intentional binding.** The public guard tries another provider after a null result, stops on `AuthenticationError`, and rethrows other errors (a store outage is not an invalid password). Cookie validation returning no user also discards its session. A wrong-realm request must not delete/renew another realm's valid session or fall through to an unintended credential method. Use public registration/extension/transport seams, not private vendor helpers or patches. Generic library `mfa: 'verified'` is not S0's actual fresh TOTP assurance.
5. **Transport completion and operational work are separate.** Successful cookies/tokens/results must not escape before required COMMIT; rollback/error responses must not carry newly minted credentials. Intended reuse revocation and required MFA-failure counts must survive denials. Library events remain diagnostics, not durable audit/outbox. Shutdown hooks are not reset-request APIs or a mail queue; the old prototype used them only to inspect a memory sink.

## 3. Proposed I1 scope—not authorized or run here

**I1-A, first gate:** refine the external adapter/coordinator boundary and generated client in the **same two-importer graph**, then rerun all four selected published store contracts with their assertions unchanged. Account locking/transaction lifecycle may be supplied explicitly by a documented test factory, but it must not rewrite records/assertions, disable concurrency or add a contract-only security bypass. Separate generic persistence semantics from owned credential/grant issuance policy: optional claims still round-trip absent, late successors cannot clear family tombstones, and the live gate must never authenticate a dead grant. Prefer server-owned transaction/relationship bindings over turning arbitrary refresh claims into hidden mandatory store fields. If the public contract and safe authority design cannot both be satisfied, stop and bring back that conflict before I1-B.

**I1-B, only after A passes:** exercise the real registered providers and `AuthenticationGuard` through loopback HTTP in independent service processes, using the durable account/grant coordinator and explicit server-owned projection to the unchanged S0 policies. A direct call to an IPC verifier/state method is not the acceptance path. There must be no public seed/sign/fault/clock endpoint, synthetic successful fallback identity or client actor DTO. Private runner controls may coordinate synthetic fixtures only.

Use maintained public hashing/session/token/reset/verification/MFA services. Retain the typed `Prisma.TransactionClient` boundary, no root-client casts/nested transactions or implicit global-write fallback. Authentication/write-context ownership must cover cookie validation/touch/discard as well as principal resolution; a controller-only transaction cannot retroactively cover provider work. Sensitive fixture mutations require their own coordinated current-authority recheck, not only a previously allowed guard snapshot.

Use fixed trusted verifier configuration and server-owned allowlisted test claims. Keep stable internal user IDs, personal/operator scope, lifecycle, verified email, current authentication/grant revision, exact capability and actual method/time distinct. Prototype realm/claim/table names, timeouts and capability labels stay test-only. Staff TOTP must be verified by the actual maintained service and stamped on the server; enrollment, recovery, generic MFA, JWT `iat` or a frontend field cannot create fresh TOTP. Do not expose credentials, full principals or private fixture state through probe responses/logs.
